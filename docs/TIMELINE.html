This page reconstructs those days from the artifacts they left behind — what got built, what got decided, and what the numbers say about how the work actually ran.

01

The shape of the ten days

Three quarters of the work happened in the last three days. That is not a sprint at the end of a slow start — it is what happened once the pieces stopped needing each other in sequence. The first week built one thing at a time because each layer had to exist before the next one could be written against it: archive, then importer, then index, then a terminal client. From 4 August onward the work fanned out across parallel git worktrees, one branch per feature, each merging as a separate pull request. The two peaks below, 67 and 127 commits, are that change of method showing up in the log.

The one habit visible in every day

Decisions get written down before or alongside the code that depends on them, and the measurement that settles a question gets recorded even when the answer is no. The prefix index was benchmarked and then rejected on the measurement. The choice of Swift over a web front end came out of a spike, not a preference. The theme layer landed one day before the views that would otherwise have hardcoded colours. Twenty-five ADRs in ten days is the trace of that habit.

The whole skeleton, written down before it was built

The project opened with documents, not code: a glossary of conversation and archive vocabulary, a decision log, an architecture sketch, a backlog, and a README. Twenty ADRs were written the same day, and they are still the load-bearing ones — the raw archive is the source of truth and the index is disposable, ids are stable and source-native, a conversation is a DAG rather than a list, SQLite with FTS5 is the entire storage and search layer.

A throwaway proof of concept compared TypeScript against Rust on the real corpus rather than on a benchmark, which settled the language question with numbers. Then the stack went in end to end: the archiver (workspace, config, machine identity, an append-only manifest, change detection, and APFS clone capture so 2.2 GB cost about 2 MB of disk), the cs binary, the core with its normalized model and BM25 search, and three importers in a row — ChatGPT export, Codex rollouts, Claude Code.

A prior-art survey landed mid-day and disproved two of the project's own assumptions, then had to be revised again a few commits later when the category leader turned up. The day closed with results grouped by conversation, prefix typeahead, and a performance change that halved the index by clipping tool text.

bd init landed and 90 issues went in at once, with the rule written down in the same breath: BACKLOG holds framing, beads holds the work. Most of the 30 closures are day one being recorded retroactively, so the tracker starts life already reflecting reality rather than aspiration.

The real fixes were about honesty. ymd() rendered dates in UTC, so any conversation held in the evening showed tomorrow's date; the fix moved local-day rendering into cs-core so every client reads one answer instead of deriving its own. That is the origin of a convention the project still states: a rule lives in exactly one place. The archiver stopped overstating disk cost by reporting what a clone actually occupies rather than what the files claim. A blank query now falls back to recent conversations, and the Gemini CLI importer landed.

03Thu30 Jul

A terminal you can actually search in

24commits
+14,537lines added
−918removed
61files
31issues closed

engine 38% · clients 38% · process 14% · docs 9%

The biggest single day of the first week, and the day the project got a face. A native TUI replaced the fzf shell script: in-process against cs-core, holding a query until it can mean something, folding the preview, reading in conversation order, and taking the mouse. Matching text is highlighted from spans the search already computed rather than re-derived, and a fix made tool results say honestly which ones failed.

Underneath it, a five-commit refactor parsed the query once, into a value: rename query.rs to commands.rs, split SearchOptions out of Query, add a real parser with Query/Filter/Mode, rank and mark from the parsed form, and have the TUI read the mode instead of computing it again. Two performance fixes followed the same shape — mark a conversation in one trip instead of one per message, and stop re-measuring the whole prefix on every keystroke.

An eval harness landed that harvests real searches as ground truth and scores against them, so ranking changes could be argued with data. The claude-desktop importer picked up transcripts that were already on disk.

A short day with two decisions in it. agent:, dir: and date: became filters parsed out of the search string itself, which is the beginning of the query grammar the GUI later builds rails for. And cs explain learned that a filter can be the reason a conversation is missing — before this it always blamed the tokenizer, which made it confidently wrong.

The breaking change was about reopening: destinations now resolve at action time rather than import time, so what Enter does is decided when you press it and not when the transcript was parsed. That is what lets the TUI hand the terminal to the agent it launches.

Measure it, then say no

Should the FTS tables carry a prefix index? It is most of what a broad keystroke costs, so the question was worth real work: a bench harness first, then a price, then a written rejection on the measurement. The same day settled ADR 8's rename precedence and labelled every still-open ADR with what it blocks, so the decision log stops being a list and starts being a dependency graph.

Two breaking changes tightened the same seam from both sides. The TUI stopped keeping a second source of truth beside the query text and now filters by rewriting the text itself. And a result set is marked in one decision rather than one insert per snippet.

One fix was purely about not lying: reasoning is searched by nobody and previewed by everybody, and the two places that implied otherwise now say so. cs archive went quiet unless it captured something, because it runs on a schedule every five minutes and almost every run has nothing to say.

A design day, and the measurement that shaped the rest

4commits
+6,341lines added
−187removed

Four commits, six thousand lines, and almost all of it in poc/ui. An interface prototype for a native surface, built against the real index rather than mock data, then a visual pass over it: polish, a two-axis detail control, and a way to see what a conversation actually did.

The same day the corpus itself got measured — 3,059 conversations, 184,099 messages — and the finding redirected everything after it. Conversation archetype is about 87% predicted by which tool produced it, most matches land in tool traffic rather than prose, and every attempt to group by subject came out mediocre while every structural signal came out strong and free. That is why the grouping, facets and timeline work later leans on structure — when, where, how long, which agent — and not on topics.

Four branches at once, and a contract to build clients against

The method changes here. Four feature branches ran in parallel worktrees and landed together as PR #5 — the largest of the project at +11,806 lines — carrying the block model into cs-core, a conversation's shape on every result row, a surface token layer with four visual directions solved against it, and a Swift spike. The spike is what settled the client language: Swift over a web front end, decided on what it measured rather than on preference.

A second round the same day made the core safe to build clients against. The index now builds beside the live one and swaps in whole, so a rebuild is no longer invisible and a partial answer can no longer look complete. cs search --json got a written contract — field by field, nulls included — with a test that parses the tables out of the document itself, so the doc and the code cannot drift apart silently. The reply to a search became a core-owned Answer type; the search family went private and answer() became the only door.

Google Takeout landed as four formats behind one source id. And cs init stopped silently omitting 69% of the corpus on a new machine — it now names what no detection can find, at init and once a day after.

The largest day by every measure, and the one with the clearest method: one pull request per piece of the app, twenty-four of them, each built in its own worktree against a core that had been made stable the day before.

The order matters. The app shell went in first, then the theme seam — a generated token layer landed deliberately ahead of the views that would otherwise have hardcoded colours, which is why six visual directions could be shipped in one binary later the same day. Then the result row, the reader pane on a coloured spine, facets and opening a conversation where it lives, grouping with a Library view, the minimap, folding sections with the cursor walking the heads, appearance and theme separated into two independent axes, a settings window at Cmd-comma, Gruvbox and Solarized ports with every lightness re-solved, and a bottom drawer timeline whose scrubber writes date:A..B back into the query line.

CI arrived the same day and does exactly one thing: compile the branch against main before a human merges it. The app also learned to record abandonment — the half of the query log that is not a success — so failure to find something is data rather than silence.

Two pieces of vocabulary got settled. A sitting is a result nothing can open, and cs show now renders the sitting rather than one record inside it. And the model became a property of the message that ran, with the conversation's label a summary of those — which is what fixed two importers quietly disagreeing about which model a conversation used.

Where it stands on day ten

Five Rust crates (cs-archive, cs-import, cs-core, cs-tui, cs) and one Swift app under apps/macos. 762 tests pass, none fail. Twenty-five ADRs are recorded. Of the 249 issues filed, 134 are closed, 98 remain open, 14 are deferred and 3 are in progress — so the tracker still holds roughly two-fifths of the work as outstanding, which is the honest position for a ten-day-old project with a working client.

Sources. Commit counts, line counts and file counts come from git log origin/main with local commit dates; pull requests from the GitHub API via gh, re-dated to the day their commits reached main; issue counts from the bd Dolt database, converted from UTC to local. The test figure is a cargo test --workspace run on origin/main at commit 1440386.

Two caveats worth knowing. The status table in README.md and the “Current state” table in docs/ARCHITECTURE.md both predate most of this work and understate it; CLAUDE.md still cites a 170-test suite that has since grown to 762. Neither affects the figures above, which were taken from the repository rather than from its prose.
